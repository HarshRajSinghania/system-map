# Agents in System Map

**Problem.** System Map already shows an agent's folders, tables and model services, but not the agent itself. You
can't see which agents exist, what starts each one, who it hands work to, which model it uses, where that model runs,
or when it waits for a person.

**Assumptions.**
- An agent is a named unit of work in code. v1 finds agents only in one list you point it at, or in modules you mark.
  It never guesses.
- A person sets each region. System Map never reads regions from config.
- Settings and region tags live in System Map's own data folder (`intent/`), never in the repo, the same way plan
  status does today (`core/store.py:504`).
- Turning the Agents layer on swaps the canvas to the agents picture, as in mock A. Turning it off takes you back to
  the level you were on.

## Acceptance criteria
Core, tested on a fixture repo with a list of three agents, one cron job and one spec:
1. With no agent settings, a build makes no agent nodes. The Agents tab suggests the modules that use an AI service.
2. When the settings name the list file, each object in the list becomes `agent:<name>`, with its label,
   description, jobs and `file:line` evidence.
3. An agent's status is `built` if it has at least one job. It is `planned` if it has no jobs and a plan with the
   same name exists. Otherwise it is `empty`.
4. If agent a's files contain `agent: "b"`, or a constant that resolves to `"b"`, there is a `hands_off_to` link from
   a to b.
5. A call to one of the set model-call names, or an import that reaches an AI service, gives a `uses_model` link to
   that service.
6. A cron job starts an agent when its call, or the SQL function it calls, has the agent's name in quotes. A module
   that isn't an agent starts one when its code hands work off to it.
7. A call to one of the set asks-you names marks the agent `asks you`, with the lines as evidence.
8. Set the home region to Canada and tag service S as US. Every agent that uses S is marked `leaves region`, and
   Findings shows one finding per agent, citing the call line. Clearing the tag removes both, with no rebuild.
9. After any change to settings or regions, `git status` in the repo shows nothing new.

UI, checked in the dev page (`ui/dev`) in light and dark:
10. A new **Agents** tab shows a count. Its table has the columns Agent, Status, Starts from, Model (with a region
    chip) and Asks you. The filters All, Use a model, Can leave region, Asks you and Planned show the right counts.
11. Picking a row opens the detail: description, a small picture of what goes in and out, evidence lines,
    **Show on map** and **Ask**.
12. Layers gets an **Agents** button. When it's on, the map shows:
    - agent cards, with an asks-you badge
    - what starts each agent, and its hand-offs
    - the AI services, in one dashed band per region
    - four new lines in the legend

    When it's off, the map is exactly as before.
13. An agent's Inspector has the sections Starts from, Hands off to, Uses model and Asks you. A service's Inspector
    has a Region field. Saving it updates the band and the tab.
14. With no settings, the tab explains how to point at a list. The Agents layer button is off, and its tooltip says
    why.

**Out of scope.**
- The flow view (mock C).
- Readers for agent SDKs (Claude Agent SDK, OpenAI Agents, LangGraph, Mastra). They come in the next slice.
- The eval and guardrail columns from mock B. No generic signal finds them yet.
- Reading regions from config.

## Design
- Settings in `intent/agents.json`:
  - the list file
  - jobs key (default `handlers`)
  - hand-off key (default `agent`)
  - model-call names
  - asks-you names
  - marked modules
  - home region

  Region tags go in `intent/regions.json`. AI services: Anthropic, OpenAI, and Google's AI hosts.
- New `core/agents.py` reads the list, using the TypeScript reader's masking and imports. `core/system.py` adds
  agent nodes and links after jobs. `core/store.py` merges settings, regions and region findings at load.
  `SCHEMA_VERSION` goes from 5 to 6, and the app rebuilds models when it starts.
- API: `GET /agents`, `POST /agents/settings`, `POST /regions`. MCP: one read-only `agents` tool that returns all
  agents or one.
- UI:
  - `ui/src/agents.ts` holds the pure logic (filters, counts, detail rows), with tests.
  - `Agents.tsx` is the new tab, and `graphView.ts` builds the agents picture.
  - `SystemMap.tsx` gets the badge, the new lines and the bands.
  - `Inspector.tsx` gets the agent sections and the Region field.
  - `App.tsx` adds the tab and the layer.
- Data: this changes System Map's own model format only. One-way door: no.
- Real-world check: build a real project, point the list at `src/agents/registry.ts`, and take screenshots.
- Risks:
  - Region bands need dagre clusters inside React Flow. If they fight the layout, the fallback is a region chip on
    each card, and that would be the owner's call.
  - Unrelated `agent:` keys in other code: only names that are on the list count.
